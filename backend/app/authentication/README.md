# شرح المصادقة بالدارجة

هاد الشرح كيتبع الكود الحالي، بمثال ديال مستخدم سميتو أحمد.

الفكرة فيها ثلاثة مراحل:

1. **التسجيل:** أحمد كيصاوب حساب.
2. **الدخول:** أحمد كيثبت أن الحساب ديالو بالإيميل والباسوورد.
3. **استعمال التوكن:** أحمد كيرسل التوكن فالطلبات المحمية، بلا ما يعاود يصيفط الباسوورد كل مرة.

## ١. كيفاش السيرفر كيشعل؟

من جذر المشروع كتكتب:

```bash
make
```

هاد الأمر كيوصل لهاد السطر فـ `backend/Makefile`:

```bash
uv run --env-file .env fastapi dev app/main.py --port 8000
```

شنو كيوقع؟

1. `uv` كيحمّل الإعدادات من `backend/.env`.
2. كيشعل التطبيق الموجود فـ `main.py`.
3. التطبيق كيربط مسارات المصادقة بهاد السطر:

```python
app.include_router(auth_router)
```

`auth_router` جاي من [router.py](router.py)، وفيه:

```text
POST /auth/register
POST /auth/login
GET  /auth/me
```

**المسار** هو عنوان كيستقبل نوع محدد من الطلبات.

- `POST`: هنا كنصيفطو معطيات للتسجيل أو الدخول.
- `GET`: هنا كنطلبو معطيات الحساب.

فـ [config.py](config.py)، كيتقرا المفتاح من إعدادات البيئة:

```python
JWT_SECRET_KEY = os.environ.get("JWT_SECRET_KEY")
```

وكتتحدد مدة صلاحية التوكن:

```python
ACCESS_TOKEN_EXPIRE_MINUTES = 30
```

إلا المفتاح ناقص، البرنامج كيوقف برسالة واضحة.

**المفتاح كيبقى ثابت. الثلاثين دقيقة هي مدة التوكن، ماشي مدة المفتاح.**

`backend/.env` فيه المفتاح الحقيقي، وما خاصوش يطلع لـ Git. أما `.env.example` فهو غير نموذج للإعدادات.

## ٢. أحمد بغا يسجّل حساب

أحمد كيعمر الفورم. الواجهة كتصيفط طلب لـ:

```text
POST /auth/register
```

بمعطيات بحال:

```json
{
  "username": "Ahmed123",
  "email": "ahmed@example.com",
  "password": "ExamplePass123!xyz"
}
```

هاد الشكل سميتو **JSON**: طريقة لتنظيم المعطيات اللي كيتبادلوها الواجهة والسيرفر.

### واش المعطيات صالحة؟

فـ `router.py` عندك:

```python
async def register(data: RegisterData) -> UserResponse:
```

`data: RegisterData` كتقول لـ FastAPI: **تحقق من المعطيات حسب `RegisterData` قبل ما تدخل للدالة.**

هاد الموديل موجود فـ [schemas.py](schemas.py).

| المعطى | التحقق |
|---|---|
| اليوزرنيم | من ٣ حتى ١٥ حرف، كيبدا بحرف، وكله حروف وأرقام |
| الإيميل | الصيغة ديالو صالحة، مع الحد المحدد فالـ schema |
| الباسوورد | من ١٥ حتى ١٢٨ حرف، فيه حرف كبير وصغير ورقم ورمز مقبول، وبلا مسافات |
| حروف الباسوورد | يمكن تمثيلها بـ UTF-8 بلا خطأ |

التحقق من صيغة الإيميل ما كيثبتش أن أحمد مالك داك الإيميل.

إلا أحمد نسى الإيميل أو الباسوورد قصير، الطلب كيترفض بـ **`422`**.

**فهاد الحالة، دالة `register()` ما كتبداش الخدمة ديالها أصلاً.**

### شنو هي `SecretStr`؟

الباسوورد عندك ملفوف فـ `SecretStr`. هاد النوع كيخبي القيمة فالعرض العادي ديال الموديل.

ولكن **ماشي هاش وماشي تشفير**.

باش الكود يحصل على الباسوورد الحقيقي، كيستعمل:

```python
data.password.get_secret_value()
```

النوع `Password` اللي عندك فـ `schemas.py` كيزيد التحقق من صلاحية Unicode فوق `SecretStr`، وكيتستعمل فالتسجيل والدخول.

### شكون كيجهّز جواب الخطأ؟

[validation_route.py](validation_route.py) فيه `AuthRoute`.

هاد الكلاس كيلف معالجة الطلب، وكيشد أخطاء التحقق باش يرجع غير:

- `loc`: فين كاين الخطأ.
- `type`: نوع الخطأ.
- `msg`: الشرح.

وكيحيد المعطيات الخام اللي ممكن يكون فيها الباسوورد.

## ٣. واش الحساب موجود من قبل؟

إلا المعطيات صحيحة، كتخدم دالة `register()`.

أول حاجة كتنادي:

```python
find_existing_user_id(data.username, data.email)
```

هاد الدالة فـ [memory_store.py](memory_store.py). كتقلب فـ `TEST_USERS` واش شي حساب عندو:

- نفس اليوزرنيم، **أو**
- نفس الإيميل.

كتستعمل `casefold()` باش المقارنة ما تفرقش بين الحروف الكبيرة والصغيرة.

مثلاً، `Ahmed123` و`AHMED123` كيتحسبو نفس الاسم.

إلا لقات تطابق، كيرجع **`409`**:

```json
{
  "detail": "Username or email is already registered."
}
```

إلا ما لقاتش، كيكمل التسجيل.

## ٤. السيرفر كيحسب هاش الباسوورد

فـ `router.py`:

```python
password_hash = await run_in_threadpool(
    hash_password,
    data.password.get_secret_value(),
)
```

### `hash_password`

هاد الدالة موجودة فـ [security.py](security.py).

كتعطي الباسوورد لمكتبة الهاش، اللي كتستعمل Argon2id فالإعداد الحالي، وكتحصل على نتيجة بحال:

```text
$argon2id$v=19$...
```

**الهاش هو اللي كيتخزن، ماشي الباسوورد الأصلي.**

المكتبة كتضيف قيمة عشوائية سميتها salt، ومعلومات التحقق كتكون فالهاش الناتج. لهذا نفس الباسوورد يقدر يعطي هاش مختلف كل مرة.

ملي تحتاج تتحقق من الباسوورد من بعد، المكتبة كتستعمل الهاش المخزن باش تعرف واش كيطابقو. ما كتحتاجش ترجع الهاش للباسوورد الأصلي.

### `run_in_threadpool`

حساب الهاش كيستهلك وقت وموارد. هاد الدالة كتخليه يخدم فـ thread ديال الخدمة، باش ما يشدش الحلقة الرئيسية اللي كتعالج طلبات السيرفر.

### `await`

كتعني: **تسنّى نتيجة هاد العملية، وخلي السيرفر يقدر يخدم طلبات أخرى فهاد الوقت.**

## ٥. الحساب كيتخزن

من بعد الهاش:

```python
user = create_user(
    data.username,
    data.email,
    password_hash,
)
```

`create_user()` كتدير:

1. كتعاود تتأكد أن اليوزرنيم والإيميل ما مستخدمينش.
2. كتولد معرّف جديد باستعمال `uuid4()`.
3. كتجمع معطيات الحساب.
4. كتزيد الحساب فـ `TEST_USERS`.

شكل الحساب المخزن، بقيم توضيحية:

```python
{
    "id": "معرّف-فريد",
    "username": "Ahmed123",
    "email": "ahmed@example.com",
    "password_hash": "$argon2id$...",
}
```

### علاش كنعاودو التحقق من التكرار؟

حيت فاش الطلب الأول كيتسنى الهاش، طلب آخر يقدر يسجّل نفس الإيميل.

التحقق الثاني كيلتقط هاد الحالة فطريقة التشغيل الحالية. إلا لقى تكرار، كيطلع `DuplicateUserError`، و`register()` كتحولو لجواب `409`.

هاد الحماية ما كتعوضش قيود منع التكرار فقاعدة البيانات ملي تزيدوها.

### فين تخزن الحساب؟

**فالذاكرة ديال البرنامج.**

`TEST_USERS` لائحة Python، ماشي قاعدة بيانات وماشي ملف.

إلا تعاود شعلتي السيرفر، الحسابات كتمسح. وكل عملية سيرفر مستقلة عندها اللائحة ديالها.

## ٦. شنو كيرجع التسجيل لأحمد؟

الدالة كتبني:

```python
UserResponse(
    id=user["id"],
    username=user["username"],
    email=user["email"],
)
```

والسيرفر كيرجع **`201`** ومعاه:

```json
{
  "id": "معرّف-فريد",
  "username": "Ahmed123",
  "email": "ahmed@example.com"
}
```

ما كيرجعش الباسوورد ولا الهاش.

**التسجيل الحالي كيصاوب الحساب فقط. ما كيخرجش توكن؛ أحمد خاصو يدير الدخول.**

## ٧. أحمد بغا يدخل للحساب

كيصيفط:

```text
POST /auth/login
```

مع:

```json
{
  "email": "ahmed@example.com",
  "password": "ExamplePass123!xyz"
}
```

أولاً، `LoginData` كيتحقق من الإيميل والباسوورد. الباسوورد فالدخول خاصو يكون من حرف واحد حتى ١٢٨، وبـ Unicode صالح.

الدخول ما كيعاودش يفرض شروط تعقيد إنشاء الباسوورد؛ الهدف هو مقارنة السر المدخل بالهاش المخزن.

من بعد `login()` كتنادي:

```python
user = await authenticate_user(
    data.email,
    data.password.get_secret_value(),
)
```

هاد الدالة فـ [service.py](service.py).

### أ. كتقلب على الحساب بالإيميل

```python
user = find_user_by_email(email)
```

### ب. كتجيب الهاش ديالو

```python
password_hash = user.get("password_hash") if user is not None else None
```

### ج. كتتحقق من الباسوورد

كتشغّل `verify_password()` فـ thread الخدمة:

```python
verify_password(password, password_hash)
```

- إلا مطابق: النتيجة `True`.
- إلا ما مطابقش: النتيجة `False`.

المقارنة ماشي بين النص ديال الباسوورد والنص ديال الهاش؛ مكتبة الهاش هي اللي كتدير التحقق.

إلا الهاش غير معروف للمكتبة، الكود كيرجع `False` بدل ما يخلي الطلب يطيح بخطأ داخلي.

### د. كتقرر النتيجة

إلا الحساب ما كاينش، أو ما عندوش باسوورد محلي، أو الباسوورد غلط، كترجع `None`.

و`login()` كيرجع **`401`**:

```json
{
  "detail": "Invalid email or password"
}
```

نفس الرسالة للإيميل المجهول والباسوورد الغلط.

### علاش كاين `DUMMY_PASSWORD_HASH`؟

إلا الإيميل ما موجودش، أو الحساب ما عندوش هاش، الكود كيدير تحقق باستعمال هاش وهمي.

الهدف هو ينقص الفرق فالوقت بين إيميل موجود مع باسوورد غلط، وإيميل ما موجودش.

هاد الهاش **ماشي حساب، وما كيعطي حتى واحد حق الدخول**. حتى إلا طابق الباسوورد الوهمي، الكود كيرفض الحساب اللي ما عندوش باسوورد محلي.

## ٨. الدخول نجح: كيتصاوب التوكن

`login()` كينادي:

```python
access_token = create_access_token(user["id"])
```

فـ `security.py`، كيتوجد المحتوى ديال التوكن:

```python
payload = {
    "sub": user_id,
    "iat": now,
    "exp": now + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES),
}
```

| الحقل | المعنى |
|---|---|
| `sub` | معرّف أحمد |
| `iat` | وقت إصدار التوكن |
| `exp` | وقت انتهاء الصلاحية |

من بعد:

```python
jwt.encode(
    payload,
    JWT_SECRET_KEY,
    algorithm=JWT_ALGORITHM,
)
```

المكتبة كتنتج توكن موقّع باستعمال المفتاح السري والخوارزمية `HS256`.

**التوقيع كيخلي السيرفر يكشف واش التوكن تبدّل أو تصاوب بلا المفتاح ديالو.**

المحتوى ديال JWT قابل للقراءة؛ التوقيع ماشي تشفير للمحتوى. لهذا ما كنحطوش فيه الباسوورد.

السيرفر كيرجع لأحمد:

```json
{
  "access_token": "eyJ...",
  "token_type": "bearer"
}
```

**التوكن ما كيتكتبش فـ `.env`، وما كيتزادش فـ `TEST_USERS`.** كيرجع للواجهة باش تستعملو فالطلبات.

## ٩. أحمد بغا يشوف الحساب ديالو

دابا ما محتاجش يصيفط الباسوورد من جديد.

كيصيفط:

```http
GET /auth/me
Authorization: Bearer eyJ...
```

السطر `Authorization` هو معلومة كترافق الطلب، والتوكن كيتحط من بعد `Bearer`.

فـ `router.py` عندك:

```python
Depends(get_current_user)
```

المعنى: **قبل ما تنفذ `/me`، نفّذ `get_current_user()` وجيب المستخدم.**

الدالة موجودة فـ [current_user.py](current_user.py).

كتدير:

1. كتخرج التوكن من الطلب باستعمال `HTTPBearer`.
2. إلا ما كاينش، كترفض بـ `401`.
3. كتنادي `decode_access_token()`.
4. كتخرج معرّف المستخدم من التوكن الصحيح.
5. كتقلب على الحساب بهاد المعرّف.
6. إلا الحساب موجود، كترجعو لـ `/me`؛ إلا ما موجودش، كترفض بـ `401`.

### شنو كتدير `decode_access_token()`؟

كتستعمل `jwt.decode()` باش تتحقق من:

- التوقيع باستعمال المفتاح السري.
- الخوارزمية المقبولة.
- الصلاحية وحقول الوقت اللي كتفحصها المكتبة.
- وجود `sub` و`iat` و`exp`.

والكود ديالك كيزيد يتحقق من أنواع الأوقات وصحة شكل معرّف المستخدم.

**غير قراءة محتوى التوكن ما كافياش؛ خاص التحقق من التوقيع والصلاحية.**

إلا كلشي صحيح، `/me` كيرجع معلومات أحمد بـ **`200`**، بلا الباسوورد والهاش.

## ١٠. شنو كيوقع بعد ٣٠ دقيقة؟

مثلاً، أحمد دخل مع **١٠:٠٠**:

```text
وقت الإصدار: ١٠:٠٠
وقت الانتهاء: ١٠:٣٠
```

مع **١٠:٣١**، إلا صيفط نفس التوكن لـ `/auth/me`:

1. `jwt.decode()` كيلقى أن الصلاحية سالات.
2. الطلب كيترفض بـ `401`.
3. أحمد خاصو يعاود الدخول باش ياخذ توكن صالح.

**ما كاين حتى مؤقّت كيتسنى ٣٠ دقيقة باش يمسح التوكن.** التحقق من الوقت كيوقع ملي كيوصل الطلب.

وما كاينش عندك تجديد تلقائي للتوكن دابا.

المفتاح السري ما كيتبدّلش فهاد العملية. إلا بدّلتو نتا، التوكنات الموقعة بالمفتاح القديم ما كتبقاش مقبولة عند السيرفر بالإعداد الحالي.

| [validation_route.py](validation_route.py) | كينقّي أخطاء التحقق باش ما تكشفش الباسوورد |
| [memory_store.py](memory_store.py) | كيقلب على الحسابات وكيخزنها مؤقتاً |

## ١٢. الخريطة اللي خاصك تبقى عاقل عليها

**التسجيل:**

```text
معطيات → تحقق → منع التكرار → هاش الباسوورد → تخزين → جواب
```

**الدخول:**

```text
إيميل وباسوورد → إيجاد الحساب → فحص الباسوورد → إصدار توكن
```

**طلب محمي:**

```text
توكن → فحص التوقيع والصلاحية → إيجاد الحساب → تنفيذ الطلب
```

| الرمز | المعنى فهاد المسارات |
|---|---|
| `200` | الطلب نجح |
| `201` | الحساب تصاوب |
| `401` | بيانات الدخول أو التوكن غير مقبولين |
| `409` | اليوزرنيم أو الإيميل مستخدم من قبل |
| `422` | المعطيات ما موافقاش القواعد |

أربعة حوايج مختلفين، ما تخلطش بينهم:

- **الباسوورد:** السر اللي كيعرفو المستخدم.
- **هاش الباسوورد:** النتيجة اللي كتخزنها باش تتحقق من الباسوورد.
- **مفتاح JWT:** السر ديال السيرفر اللي كيوقّع ويتحقق به من التوكنات.
- **التوكن:** الوثيقة المؤقتة الموقعة اللي كياخذ المستخدم وكيصيفطها فالطلبات المحمية.

هاد الشرح كيغطي المسارات الحالية. التخزين الدائم، تأكيد ملكية الإيميل، والدخول بغوغل ما داخلينش فهاد التدفق الحالي.
